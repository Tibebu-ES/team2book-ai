# Mise en production et transition vers Team2Book

## Introduction

Après avoir complété la configuration et la formation des utilisateurs, l'organisation est prête à utiliser Team2Book dans un contexte réel.

Cette étape consiste à valider la configuration, comparer les résultats avec l'ancien processus et effectuer une transition progressive vers la nouvelle méthode de travail.

Une transition graduelle permet :

- de réduire les erreurs;
- de rassurer les utilisateurs;
- d'identifier les ajustements nécessaires;
- d'assurer une adoption durable.

---

# Étape 13 — Comparaison avec l'horaire existant

## Objectif

Avant d'abandonner l'ancien processus de production des horaires, il est recommandé de comparer les résultats obtenus avec Team2Book avec l'horaire actuel de l'organisation.

Cette étape permet de valider que :

- les règles d'affectation sont correctement configurées;
- les priorités sont respectées;
- les préférences de ressources sont appliquées;
- les contraintes fonctionnent correctement.

---

# Procédure de validation

Le gestionnaire d'équipe doit :

1. Entrer les disponibilités des consommateurs pour une période donnée.
2. Produire les affectations avec Team2Book.
3. Comparer les résultats avec l'horaire existant.

La période de comparaison peut être :

- la semaine suivante;
- le mois suivant;
- une autre période représentative.

---

# Points à vérifier

## Attribution des ressources

Vérifier que :

- les bureaux attribués correspondent aux attentes;
- les préférences des consommateurs sont respectées;
- les priorités sont appliquées correctement.

---

## Problèmes de planification

Consulter :

**Tableau de bord → Planificateur**

Analyser les problèmes détectés.

Exemples :

- ressources insuffisantes;
- consommateurs non assignés;
- contraintes non respectées.

---

## En cas de différence avec l'ancien horaire

Si Team2Book produit un résultat différent de l'horaire existant :

Vérifier :

1. Les priorités des consommateurs.
2. Les ressources réservées.
3. Les préférences de ressources.
4. Les contraintes configurées.
5. Les disponibilités saisies.

Une différence ne signifie pas nécessairement une erreur. Elle peut indiquer une amélioration possible du processus.

---

# Étape 14 — Demander aux consommateurs d'entrer leurs disponibilités

## Objectif

Après validation de la configuration, les consommateurs peuvent commencer à utiliser Teamup directement pour déclarer leurs disponibilités.

Cette étape remplace progressivement les méthodes traditionnelles :

- courriels;
- formulaires papier;
- fichiers Excel;
- communications manuelles.

---

# Nouvelle méthode de travail

Les consommateurs doivent :

1. Accéder à Teamup Calendar.
2. Entrer leurs disponibilités.
3. Entrer leurs indisponibilités lorsque nécessaire.
4. Vérifier leurs informations avant la date limite.

---

# Rôle du gestionnaire d'équipe

Durant les premiers cycles, le gestionnaire doit :

- vérifier les disponibilités saisies;
- identifier les erreurs;
- accompagner les utilisateurs;
- répondre aux questions.

---

# Vérifications recommandées

Le gestionnaire doit vérifier :

## Disponibilités

- Les disponibilités ont-elles été correctement saisies?
- Les périodes correspondent-elles aux besoins?

---

## Erreurs du planificateur

Consulter :

**Tableau de bord → Planificateur**

Corriger ou expliquer les problèmes détectés.

---

## Accompagnement des utilisateurs

Lorsque des erreurs fréquentes apparaissent :

- expliquer la cause;
- montrer la bonne méthode;
- ajuster la formation au besoin.

---

# Étape 15 — Abandon de l'ancien processus et utilisation complète de Team2Book

## Objectif

Lorsque l'organisation est suffisamment à l'aise avec Team2Book, elle peut abandonner progressivement son ancien processus de production des horaires.

Les anciennes méthodes peuvent inclure :

- documents papier;
- fichiers Excel;
- échanges de courriels;
- planification manuelle.

---

# Nouvelle méthode officielle

L'organisation utilise maintenant :

- Team2Book pour la planification;
- Teamup Calendar pour le calendrier partagé;
- les disponibilités entrées directement par les consommateurs.

---

# Période d'adaptation finale

Même après la mise en production, une période d'adaptation est normale.

Prévoir :

- environ 2 à 3 cycles d'utilisation.

Durant cette période :

- les utilisateurs deviennent plus autonomes;
- les erreurs diminuent;
- les processus deviennent naturels.

---

# Suivi recommandé après la mise en production

Le gestionnaire d'équipe devrait effectuer un suivi régulier.

Vérifier :

- les problèmes de planification;
- les ressources non attribuées;
- les contraintes déclenchées;
- les questions des utilisateurs.

La section à surveiller est :

**Tableau de bord → Planificateur**

---

# Gains attendus

Après l'adoption complète de Team2Book, l'organisation peut généralement bénéficier :

- d'une réduction importante du temps consacré à la production des horaires;
- d'une meilleure visibilité des disponibilités;
- d'une diminution des conflits de ressources;
- d'une meilleure équité dans les affectations;
- d'une réduction des tâches administratives répétitives.

---

# Conclusion de l'intégration

Félicitations!

Si les étapes décrites dans ce guide ont été suivies, l'organisation devrait maintenant être en mesure d'utiliser Team2Book efficacement.

Les éléments essentiels d'une intégration réussie sont :

- une bonne préparation;
- un gestionnaire d'équipe impliqué;
- une formation adaptée;
- une configuration réfléchie;
- une transition progressive.
